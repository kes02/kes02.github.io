## Web Server?
HTTP 또는 HTTPS를 통해 웹 브라우저에서 요청하는 HTML 문서나 오프젝트(이미지 파일)과 같은 정적인 컨텐츠를 제공하는 컴퓨터 프로그램

## WAS?
DB조회나 다양한 로직 처리를 요구하는 동적인 컨텐츠를 제공하기 위해 만들어진 Application Server
== 웹 컨테이너 혹은 서블릿 컨테이너라고도 불린다. 
SpringBoot에서는 DispatcherServlet이 이와 같은 역할을 한다.

## Web Server가 필요한 이유
WAS = Web Server + Web Container 로 웹서버 없이 WAS만으로도 서버 운영이 가능하다. 실제로 우리는 프로젝트에서 AWS EC2에 서버(WAS)라고 하는 것으로 운영한다.

그러나 만약 우리가 클라이언트에게 정적 콘텐츠 만을 보낸다면? WAS를 굳이 사용하지 않고도 보낼 수 있다. 이는 WAS의 부담을 줄여주게 된다.

## WAS가 필요한 이유
요즘 개발되는 다양한 웹서비스에는 정적인 콘텐츠만을 사용자에게 제공하지 않는다. 이는 Web Server 만으로는 동적 콘텐츠를 제공하기엔 절대적으로 어렵다는 것이다.

그렇기에 WAS를 사용하여 정적/동적 콘텐츠를 제공하며 비즈니스 로직에 맞는 결과를 제공할 수 있다.

## 우리는 Web Server + WAS를 사용해야 한다?
그렇다. 웹 서버만으로는 정적/동적 콘텐츠를 제공하기 어렵고, 이는 WAS만으로 운영하는 것도 사실 반쪽자리의 서버 운영이라고 생각한다. 

두 가지를 같이 사용한다면 이점도 존재한다.
1. 기능을 분리함으로써 서버 부하 방지
2. 물리적으로 분리하여 보안 강화
3. Web Server로 부터 여러대의 WAS 연결 가능(로드밸런싱과 같은 효과)
4. 여러 웹 애플리케이션 서비스 가능

즉, 자원 이용의 효율성과 장애 극복, 배포 및 유지보수의 편의성을 제공할 수 있다.
