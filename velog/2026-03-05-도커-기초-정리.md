## 도커는 왜 필요할까?
프로젝트를 진행하게 되면 반드시 서버가 필요하다. 그리고 이 서버를 개발하는 사람들이 1명이 아닌 여러명이 있게 되는데 이때 여러 명의 개발환경은 다 다를 것이다.
이로 인해 A라는 사람의 개발환경에서는 실행되는 코드가 B라는 사람의 개발환경에서는 실행되지 않을수도 있다.
그리고 프로젝트에 새로운 사람이 참여하게 되거나, 새로운 개발환경을 다시 세팅해야될 때도 같은 문제가 계속해서 발생할 수 있다. 
우리는 이러한 문제를 도커를 통해 간단히 해결할 수 있기 때문에 도커를 사용하게 된다.

## 도커는 어떤 방식으로 사용되는가?
우리가 주로 사용하는 윈도우와 맥에서는 도커 데스크톱이라는 프로그램을 다운 받아 사용할 수 있다.
이 도커 데스크탑의 경우 도커 엔진을 통해 컨테이너가 실행되게 된다.
여기서 컨테이너란? 하나의 작은 서버 라고 할 수 있을 것 같다.

### 컨테이너?
컨테이너란 이름을 처음 들었을 때 딱 생각할 수 있는건 배 위에 여러개의 컨테이너가 쌓인 모양을 상상할 수 있다. 그리고 이 도커는 여러 개의 컨테이너가 실행될 수 있는데, 이 모습이 우리가 상상하는 그것과 닮아 도커의 로고도 아래와 같은 모양이다.

### 도커엔진?
도커엔진은 왜 필요할까? 도커 엔진은 OS를 대신하는 게 아 컨테이너를 관리해주는 '관리자' 역할을 한다.
우리가 알고 있는 VM과 비슷한 모양이라고 생각할 수 있는데, 여기서 VM과의 차이를 확실히 알아야한다.

## VM과 도커의 차이는?
VM은 Virtual Machine의 약자로 각각의 가상머신마다** Guest OS를 설치**해야하기 때문에 무겁고 느리다.
도커는 호스트의 **커널을 공유**하기 때문에 별도의 OS 설치가 필요없고, 실행속도가 빠르다.

## 이미지가 뭘까?
이미지라는 단어를 처음 들었을 때는 정말 image 그 자체를 생각해선 안된다. 
여기서 말하는 이미지란 **설계도**라고 할 수 있다. 그리고 컨테이너는 인스턴스 즉, 설계도를 보고 짓는 건물이라고 할 수 있다.
그렇기 때문에 이 이미지의 역할이 도커에서 가장 중요하다고 할 수 있다.
이 이미지는 Dockerfile을 작성하여 만들 수 있게 된다.
즉, Dockerfile을 생성 -> build -> 이미지 생성 순이다.

### 이미지를 좀 더 자세하게 알아보자
도커에서의 이미지는 레이어 구조이다. Dockerfile을 보게된다면 아래와 같이 이루어져있다.
- Base Layer: OS (ex. Ubuntu)
- Middle Layer: 언어/런타임 (ex. Python 3.9)
- Upper Later: 소스 코드 (ex. FastAPI app)
- Top Layer: 실행 명령어 (ex. uvicorn main:app)

이 레이어의 장점으로는 재사용성, 저장 공간 절약이 있다.
- 재사용성: Dockerfile에서 코드 한줄만 수정해서 이미지로 다시 사용 가능
- 저장 공간 절약: 내 컴퓨터에서 실행 중인 10개의 파이썬 3.9 앱에는 파이썬 3.8 레이어 하나만을 공유해서 쓸 수 있다.

### 도커 엔진 명령어 정리
도커를 설치하고 나면 CLI에 docker --version을 작성해보자. 실행이 된다면 정상적으로 도커를 설치한 것이다.
- docker run [이미지 이름]: 도커에 존재하는 이미지를 컨테이너로 실행시킨다.
- docker stop [컨테이너 이름]: 도커에서 실행중인 컨테이너를 중지시킨다.
- docker start [컨테이너 이름]: 중지한 컨테이너를 다시 실행시킨다.
- docker rm [컨테이너 이름]: 컨테이너를 삭제한다. 이때 컨테이너 내부의 데이터도 삭제되니 따로 관리해야할 데이터는 마운트를 해서 관리해야한다.
- docker ps: 현재 실행 중인 컨테이너가 뭔지 볼 수 있다.

### docker-compose.yaml
앞에서 본 것처럼 docker run으로 컨테이너를 하나씩 띄우는 건 생각보다 번거롭다. 만약 내 프로젝트에 서버, DB 가 필요하다면? 매번 필요한 개수만큼의 명령어를 치고, 서로 IP를 연결해 주는 귀찮은 일을 해야 한다.
이 귀찮음을 해결해 주는 구세주가 바로 **도커 컴포즈(Docker Compose)**이다.

도커 컴포즈를 쓰면 좋은 점:
- 한 번에 실행: up 명령어 하나로 여러 컨테이너를 동시에 띄운다.
- 네트워크 자동 연결: 컨테이너끼리 서로의 이름(서비스명)으로 쉽게 연결
- 의존성 관리: "DB가 켜진 후 서버를 띄워라" 같은 순서를 정할 수 있다.

## 이외에도
docker hub을 통해 여러 기업 또는 사용자들이 올려둔 이미지를 무료로 다운 받을 수 있다. 
필요에 따라 MySQL이나 Redis를 직접 설치하지 않고도 이 이미지를 통해 사용할 수 있다.
