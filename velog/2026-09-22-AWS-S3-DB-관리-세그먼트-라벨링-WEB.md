### 배경
해당 페이지는 정말 세그먼트 데이터 라벨링에만 특화되어서 만들었다. 앞에서 보았듯이 S3데이터가 들어오게 되었을 때 우리는 3인이라는 고급 인력을 활용해 데이터 라벨링을 해야했다. 그런데 백오피스에서는 라벨을 찾고, 메모를 하고, 누가 무엇을 했는지 조차도 확인이 어려웠다. 

그래서 모델 학습을 위한 세그먼트 데이터 라벨링 일을 각자에게 부여하기 위해 만든 페이지이다.
해당 페이지는 로컬에서 동작하며 라벨링이 완료되었을 시 해당 Repo로 PR을 올리는 방식으로 데이터를 병합하였다.

## 2. 세그먼트 라벨링 WEB
### 라벨링 화면
라벨링의 전체 화면은 다음과 같다.
백오피스 처럼 음원을 다음과 같이 들을 수 있고 LABEL이라는 것에 있는 번호에 맞춰 키보드를 누르거나 버튼을 누르면 라벨이 자동으로 추가가 된다.
만약, 원하는 라벨이 없다면 백오피스에 라벨이 존재하는지 확인하고 라벨을 새로 넣으면 된다.
![](https://velog.velcdn.com/images/kes02/post/05b3f0e2-78a8-4895-a225-8fcca4cf5ed9/image.png)

### 데이터 묶음 기능
사람 3명에서 각 묶음별로 데이터 라벨링 일을 할당해서 작업을 진행했다. 
덕분에 데이터 라벨링을 중복 처리하지 않고, 각자 맡은 일을 빠르게 처리가 가능해졌다.
<img src="https://velog.velcdn.com/images/kes02/post/172573ba-5514-4166-b764-a6527504eabd/image.png" width="50%">

### 비앵무/앵무 후보 데이터 확인도 가능
기존에 약 2000개의 데이터로 학습한 v1.0.0 앵무새 분류 모델을 기반으로 미리 앵무/비앵무 후보를 볼 수 있었다.
실제로 라벨링을 하다보니 아무래도 생활 잡음이나 무음이 많이 들어가있었고 라벨링을 하게 되면 비앵무 쪽으로 데이터 치우침 현상이 발생했다. 
이를 방지하기 위해 중반 작업 부터는 각자 맡은 데이터 묶음에서 '앵무 후보'로 추측된 데이터만 라벨링 하였다.
<img src="https://velog.velcdn.com/images/kes02/post/561f5aa7-6dcd-457d-8344-87b928168e37/image.png" width="40%">

### 세그먼트 오디오 라벨링 영상
이렇게 3명이서 라벨링한 데이터 양만 2.5만건 정도 된다.
