Alledin

개발 배경

문제업체별 음식 메뉴의 알레르기 정보 파편화

  • 메뉴별 알레르기 유발 물질 정보 탐색의 어려움
  • 정리된 데이터셋 부재로 업체별 전화 문의·직접 확인 필요

해결내 알레르기와 메뉴의 즉시 비교

  • 알레르기 정보 표시 의무가 있는 프랜차이즈 중 가맹점 100개 이상 업체를 대상으로 데이터 구축 (어린이 식생활안전관리 특별법 시행령)
  • 내 알레르기 정보를 저장해 두고 메뉴를 고를 때 바로 비교

개발

알레르기 정보 등록

  • 식약처 지정 21종 중 해당 물질 선택

식당 및 음식 검색

  • 음식·음식점 이름과 현재 위치로 검색

메뉴 필터 제공

  • 유발 물질이 든 메뉴 제외

외식 가능 식당 및 음식 정보 제공

  • 내 알레르기 정보를 반영해 먹을 수 있는 식당과 메뉴 표시

문제식당 검색 지연

  • 검색 1회에 약 1분 소요
  • 메뉴마다 사용자 알레르기 정보를 다시 읽는 반복 조회

해결알레르기 정보 1회 조회로 변경

  • 알레르기 정보를 처음에 한 번만 조회한 뒤 식당·메뉴와 비교
  • 불필요한 DB 왕복을 줄여 검색 지연 해결

맡은 역할

  • 백엔드 Spring Boot 서버의 예외 응답을 Exception Enum으로 통일
  • 데이터 프랜차이즈 알레르기 데이터 수집·정리, AWS RDS에서 관리
  • 기획 초기 MVP 와이어프레임을 Figma로 설계

사용 기술

Spring Boot · Java 17　MySQL · AWS RDS　Python · CSV　Figma

데이터

문제업체별 알레르기 정보 데이터 부재

  • 식약처에 전화로 업체별 알레르기 정보 데이터를 요청
  • 수집 의무가 없어 보유 데이터가 없다는 식약처 답변

해결업체 직접 요청을 통한 데이터 확보

  • 배달의민족, 본죽 등 업체 대표 이메일로 연락
  • 대학생 팀의 비영리 목적 수집임을 설명해 데이터 직접 확보

데이터 수집

  • 가맹점 100개 이상 프랜차이즈의 위치·제품·알레르기 정보 수집

데이터 정리

  • Python·스프레드시트로 쓸 수 없는 데이터 삭제, 표기법 정규화

좌표 변환

  • 공공데이터 좌표를 지도 API 형식으로 변환

데이터 저장

  • 약 1만 건을 CSV로 정리해 AWS RDS에서 관리

시스템 구조

요청 흐름

  • Flutter 앱(Android·iOS)이 RESTful API로 Spring Boot 서버 호출
  • 서버는 JDBC로 MySQL 접근
  • 인증과 클라우드 메시징은 Firebase로 처리

운영과 배포

  • 서버는 AWS EC2, DB는 RDS에 배포
  • 서버는 Jenkins, 앱은 Fastlane으로 테스트·배포
