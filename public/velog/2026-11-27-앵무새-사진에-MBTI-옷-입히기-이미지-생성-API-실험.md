## 들어가며

[앵비티아이(BuddyBird MBTI)](https://mbti.buddybird.xyz/)는 앵무새 성향을 MBTI 16유형으로 보여 주는 웹 테스트다. 유형마다 폴리곤 스타일의 앵무새 캐릭터 일러스트가 있다. 여기서 아이디어가 하나 나왔다.

> 사용자가 **자기 앵무새 사진**을 올리면, 결과 유형 캐릭터의 옷을 입힌 이미지를 만들어 주면 어떨까?

2026년 9월 30일부터 10월 1일까지 OpenRouter 이미지 API로 직접 실험했다. 이미지 생성 요청을 **55번** 보냈고, 그중 49번은 이미지를 받았고 6번은 HTTP 400으로 실패했다. 이 글에는 실험 과정과 결과, 그리고 그 과정에서 배운 점을 정리했다.

---

## 1. 모델 고르기: 공개 가격과 실제 청구 금액은 다르다

OpenRouter에서 '사진 입력 + 이미지 출력'을 지원하는 후보부터 추렸다.

| 모델 | OpenRouter ID | 공개 가격 | 공개 E2E P50 |
| --- | --- | --- | --- |
| FLUX.2 Klein 4B | `black-forest-labs/flux.2-klein-4b` | 첫 1MP $0.014 | 5.67초 |
| Nano Banana 2 Lite | `google/gemini-3.1-flash-lite-image` | 1K 약 $0.0336 + 입력 | 5.73초 |
| Nano Banana 2 | `google/gemini-3.1-flash-image` | 1K 약 $0.0672 + 입력 | 16.83초 |
| Seedream 4.5 | `bytedance-seed/seedream-4.5` | $0.04/장 | 11.71초 |

처음에는 가장 싼 FLUX Klein을 기본 모델로 정했다. 실제 1024×1024 요청을 보내 보니 청구액은 **장당 $0.016**이었다. 예상한 $0.014보다 높았다. 1024×1024는 1.048MP로 1MP를 조금 넘는다. 다만 OpenRouter가 이 값을 어떻게 반올림해 청구하는지는 문서로 확인하지 못했다.

> 이미지 모델 예산은 공개 가격이 아니라 **응답의 `usage.cost` 실측값**으로 정해야 한다.

Gemini 계열은 텍스트 토큰 수만 봐서는 비용을 알 수 없다. 1K 이미지 1장은 출력 이미지 토큰 1,120개이고, 이미지 토큰 단가는 텍스트 토큰 단가와 다르다.

### 호출 방식

OpenRouter의 전용 이미지 엔드포인트를 썼다.

```js
const res = await fetch("https://openrouter.ai/api/v1/images", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.OPENROUTER_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "google/gemini-3.1-flash-lite-image",
    prompt,
    input_references: [userPhotoDataUrl, intjCostumeDataUrl], // 순서가 중요
    n: 1,
    // resolution, aspect_ratio 등은 모델마다 지원 여부가 다르다
  }),
});
const { data, usage } = await res.json(); // data[].b64_json, usage.cost
```

## 2. 첫 번째 방식: 내 새를 INTJ 캐릭터로 다시 그리기 (프롬프트 v01~v15)

처음 목표는 **사용자 앵무새를 앵비티아이 그림체 캐릭터로 다시 그리는 것**이었다. 입력은 사용자 사진 1장과 INTJ 캐릭터 이미지 1장이었다.

<p align="center"><img src="https://velog.velcdn.com/images/kes02/post/d65f20a7-7d4a-4dc0-bb55-47c03ec06b5a/image.png" alt="INTJ 원본 캐릭터" width="300"></p>

### v01: 참고 캐릭터의 특징이 그대로 남았다

![v01 비교](https://velog.velcdn.com/images/kes02/post/d10781c1-1e6e-4c1c-8ce4-6763092f78af/image.png)

FLUX와 Nano Banana 2 Lite에 같은 프롬프트를 넣었다. 그림체와 의상은 참고 이미지대로 나왔다. 대신 **INTJ 캐릭터의 초록 머리, 크림색 얼굴, 주황 볼이 그대로 남았다.** 사진 속 새의 회갈색 머리와 연한 부리는 거의 사라졌다. 결과는 '내 새'가 아니라 'INTJ 캐릭터를 한 장 더 그린 그림'이었다.

### v02~v08: 사진과 참고 이미지의 역할을 나눴다

프롬프트를 이렇게 고쳤다.

1. 첫 문장에서 **사진 속 새를 그릴 대상**으로 명시했다.
2. INTJ 이미지는 **그림체, 의상, 소품만** 참고하라고 제한했다.
3. 깃털 색과 의상 색을 분리해서 설명했다.
4. 종이나 색을 사진마다 직접 적지 않았다. 다른 사진에도 같은 프롬프트를 써야 하기 때문이다.

Nano Banana 2(v02)에서는 연한 부리와 밝은 눈테가 처음으로 반영됐다. 다만 모델과 프롬프트를 **동시에** 바꾼 실험이라 무엇이 효과를 냈는지는 알 수 없었다. 이후로는 한 번에 변수 하나만 바꾸기로 했다.

### v09~v15: 하나를 고치면 다른 하나가 사라지거나 바뀐다

<p align="center"><img src="https://velog.velcdn.com/images/kes02/post/2f4bbffa-b90b-4f64-842f-b1d592159984/image.png" alt="v09 결과" width="400"></p>

v09에서 원하는 그림체를 얻었다. 그 뒤로는 '원본 캐릭터의 옷, 손, 소품은 그대로 두라'는 조건을 지키게 만드는 데 집중했다. 하지만 한 부분을 고치면 다른 부분이 사라지거나 바뀌는 일이 반복됐다.

| --- | --- | --- | --- |
| v09 | Lite | 그림체 확정 | 왕관앵무의 옷과 가슴 앞 손이 사라짐 |
| v10 | Lite | 왕관앵무의 옷과 손이 유지됨 | 마카우 손이 사라지고 머리 깃이 생김 |

| v13 | Nano Banana 2 | 손, 옷, 발, 소품 모두 유지 | 돋보기 렌즈 색이 바뀜 |
| v14 | Nano Banana 2 | 얼굴이 큰 폴리곤 면으로 단순해짐 | 머리띠에 구슬 장식이 생김 |
| v15 | Nano Banana 2 | 구슬 장식이 사라짐 | 원본에 없던 큰 머리 깃이 생김 |

같은 v13 프롬프트로 비교했을 때 Nano Banana 2가 Lite보다 확실히 나았다. 대신 비용은 약 2배($0.069 vs $0.035), 시간은 약 3배(13.8초 vs 5.0초)였다.

### 투명 배경을 요청하면 체크무늬를 그린다

'투명 배경'을 요청했더니 모든 모델이 **회색, 흰색 체크무늬를 그린 불투명 이미지**를 돌려줬다. 돋보기 렌즈 안에까지 체크무늬를 그린 결과도 있었다. 결국 로컬에서 외곽의 무채색 영역만 알파로 지우는 후처리를 추가했다. 이 작업은 장당 0.1초 미만이고 API 비용은 들지 않는다.

> 이미지 생성 모델에 '투명 배경'을 요청했다면 알파 채널이 실제로 있는지 반드시 확인해야 한다.

## 3. 두 번째 방식: 사진은 그대로 두고 옷만 입히기

캐릭터로 다시 그리면 사진 속 새의 특징이 계속 사라졌다. 그래서 방향을 바꿨다. **원본 사진을 편집 대상**으로 삼고, INTJ 이미지는 **의상 디자인 참고용**으로만 쓰기로 했다.

고정 프롬프트의 핵심은 다음과 같다.

```text
Edit image 1, the user's original parrot photograph. Image 1 is the edit
target and must remain a photograph. Image 2 is a reference ONLY for the
clothing and wearable accessory designs. Never copy the reference bird's
identity, species, anatomy, feather colors, proportions, pose, ...

Preserve the exact photographed parrot: its recognizable face, eye shape
and markings, beak, ... and existing pose. Do not straighten, rotate, or
reposition the bird ...
```

### Seedream 4.5 vs Nano Banana Lite

<p align="center"><img src="https://velog.velcdn.com/images/kes02/post/caec1781-dd08-4478-a908-ad211c86eab0/image.jpg" alt="마카우 Lite 결과" width="400"></p>

| 모델 | 시간 | 비용 | 결과 |
| --- | --- | --- | --- |
| Seedream 4.5 (2K) | 36.8초 | $0.04 | ❌ 마카우가 아니라 **옆에 있던 사람에게** 조끼와 케이프를 입힘 |
| Seedream 4.5 재시도 | 40.8초 | $0.04 | ❌ 머리띠만 새에게, 나머지는 여전히 사람에게 입힘 |
| Nano Banana Lite (1K) | 7.0초 | $0.035 | ✅ 마카우에게 의상 적용, 자세가 조금 세워짐 |

Seedream 4.5는 1K 요청을 **HTTP 400으로 거절**한다. 최소 출력 픽셀 수 제한이 있어서 2K로 요청해야 한다.

코뉴어와 왕관앵무 사진에서도 Lite는 6~8초 만에 새에게 옷을 입혔다. 다만 코뉴어는 원본보다 몸이 정면을 향했고, 더 곧게 선 자세로 바뀌었다.

## 4. 고정 프롬프트 하나로 사진 8장 테스트하기

서비스에서는 사진마다 프롬프트를 고칠 수 없다. 그래서 **프롬프트를 고정**하고 조건이 다른 사진 8장을 순서대로 넣었다. 앵무새가 없는 사진(장난감, 선인장)도 일부러 섞었다.

결과는 이랬다.

- API 이미지 반환은 **8/8**이었다. 그런데 **이미지가 반환됐다고 합성에 성공한 것은 아니다.**
- 평균 13.9초, 중앙값 10.3초였다. 가까이에서 찍어 초점이 흐린 사진 1장은 39초가 걸렸다.
- 총 비용은 $0.279였다.

| 입력 | 관찰 |
| --- | --- |
| 장난감만 있는 사진 | ❌ 원본에 없던 초록 앵무새를 **새로 그려서** 옷을 입힘 |
| 선인장 사진 | ❌ 선인장과 화분을 지우고 **왕관앵무를 새로 생성**함 |
| 손에 안긴 앵무새 | 옷은 입혔지만 자세가 바뀌고 손가락과의 가림 관계가 달라짐 |
| 머리를 숙인 앵무새 | 고개를 **똑바로 세움** |
| 시계를 무는 앵무새 | 숙인 자세를 **똑바로 세움** |
| 가까이에서 찍어 초점이 흐린 사진 | 날개 끝에 **손처럼 보이는 발톱**이 생김 |
| 여러 마리 | 앞쪽 새에게만 옷을 입혔지만 고개를 돌려 얼굴을 재구성함 |

앵무새가 없는 사진을 넣으면 모델은 **앵무새를 새로 만들어 냈다.** 이 시점의 프롬프트에는 '앵무새가 없으면 생성하지 말라'는 조건이 없었다. 그래서 이 조건을 프롬프트 맨 앞에 추가하고 다음 테스트를 이어 갔다. '기존 자세를 유지하라'는 지시도 지켜지지 않았다. 고개를 숙이거나 뒤를 돌아본 새는 거의 매번 정면을 보고 곧게 선 모습으로 바뀌었다.

## 5. 오리 사진은 왜 HTTP 400을 반환했을까

생성 조건을 추가한 프롬프트로 오리 두 마리가 찍힌 사진을 넣었다. 이번에는 이미지가 생성되지 않았다.

```json
{
  "message": "Gemini could not generate an image (STOP)",
  "code": 400,
  "metadata": { "finish_reason": "STOP", "block_reason": null }
}
```

'앵무새가 없으니 거절했구나' 하고 결론 내리고 싶었다. 하지만 응답에는 **거절 이유가 어디에도 없다.** 그래서 대조 실험을 했다.

| 요청 | 결과 |
| --- | --- |
| 프롬프트 `test` 한 단어 | 400 STOP |
| `Generate an image of a red circle on a plain white background.` | 200, 이미지 1장 |
| 오리 사진 + 고정 프롬프트 (2회) | 400 STOP |
| 파일명을 `image.jpg`로 바꾼 오리 사진 | 400 STOP |
| 오리 사진만 **마카우 사진으로 교체** (나머지 동일) | 200, 이미지 1장 |

이 실험으로 확인한 사실은 세 가지다.

- API 키, 연결, 모델 지원에는 문제가 없다.
- 이미지는 base64 data URL로만 보내므로 파일명은 모델에 전달되지 않는다.
- Gemini의 `STOP`은 정상 종료라는 뜻이고, 안전 차단을 뜻하지 않는다. 모델이 이미지 없이 응답을 끝내면 OpenRouter가 이를 400 오류로 반환하는 것으로 추정한다.

### 원인은 사진 크기보다 프롬프트 조건으로 보인다

가장 유력한 원인은 프롬프트 자체다. 고정 프롬프트의 첫 문장에는 다음 조건이 들어 있었다.

```text
If image 1 contains no parrot, or the presence of a parrot is uncertain, stop without generating an image.
```

오리 사진에는 앵무새가 없으므로, 모델이 이 지시대로 이미지 없이 응답을 끝냈다고 보면 결과와 맞는다. `finish_reason`이 `STOP`이고 `block_reason`이 `null`인 것도 이 해석과 어긋나지 않는다.

사진 크기가 원인일 가능성은 낮다고 봤다.

- 오리 사진만 마카우 사진으로 바꾼 요청은 해상도, 비율, 모델, 프롬프트가 같았는데 이미지가 생성됐다.
- 오리 사진도 요청 전에 정사각형인지 확인하고 보냈다.
- 사진 없이 `test` 한 단어만 보낸 요청에서도 같은 400 STOP이 반환됐다. 사진과 관계없이 모델이 이미지를 만들지 않고 끝내면 이 응답이 나온다.

확정하려면 같은 오리 사진에 위 조건 문장만 뺀 프롬프트로 한 번 더 호출해 보면 된다. 이미지가 나오면 조건 문장이 원인이고, 그래도 400 STOP이면 다른 원인을 찾아야 한다.

> 실패 응답을 원하는 방향으로 해석하지 않으려면 **양성 대조군**(같은 조건에서 입력 하나만 바꾼 요청)을 함께 실행해야 한다.

## 6. 정리

### 숫자로 보면

- 이미지 생성 요청 **55번**: 49번은 이미지를 받았고 6번은 400으로 실패했다. 보고된 비용 합계는 $1.83이며, 400으로 실패한 요청은 usage가 반환되지 않아 합계에서 빠졌다.
- Nano Banana Lite: 장당 약 $0.035, 5~14초
- Nano Banana 2: 장당 약 $0.069, 11~21초
- Seedream 4.5: 장당 $0.04, 27~41초, 2K 이상만 지원
- FLUX.2 Klein 4B: 장당 $0.016, 6~12초. 다만 개인화 품질이 부족했다.

### 배운 것

1. **참고 이미지의 역할은 모델이 정하지 않는다. 프롬프트에서 정해 줘야 한다.** 'image 2는 의상 참고용일 뿐'이라고 명시하지 않으면 모델은 참고 이미지의 정체성까지 복사한다.
2. **'하지 마'라는 지시는 항상 지켜지지 않는다.** 자세 유지 지시와 장식, 볏 추가 금지 지시는 확률적으로만 지켜졌다. 서비스에서 막아야 할 조건이라면 모델 밖(사전 분류기, 마스크 기반 편집 등)에서 막아야 한다.
3. **API 성공과 결과물 성공은 다르다.** 8장이 모두 반환됐다고 8장 모두 합성에 성공한 것은 아니다.
4. **한 번에 변수 하나만 바꿔야 한다.** 모델과 프롬프트를 동시에 바꾼 v02는 결과가 좋았지만 원인을 알 수 없었다.
5. **비용, 시간, 토큰은 응답 실측값으로 기록해야 한다.** 반환되지 않은 값은 0이 아니라 '미반환'으로 남긴다.
