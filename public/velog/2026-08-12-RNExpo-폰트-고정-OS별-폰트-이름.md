앱 인트로 화면 아래쪽에 BuddyBird' 워드마크가 있다. 아래 코드로 작성했을 때 Android에서는 의도한 대로 Fredoka로 나오는데, iOS에서만 시스템 폰트로 여전히 표시되는 것을 확인했고 곧바로 수정하였다.

```ts
splashWordmark: 'Fredoka_600SemiBold',
```

## 임베드된 폰트는 OS마다 다른 이름으로 찾는다

원인은 `expo-font` config plugin은 빌드할 때 폰트 파일을 네이티브에 심는데, 심는 위치와 런타임에 그 폰트를 찾는 키가 플랫폼마다 다르다.

| | 심기는 위치 | 런타임 조회 키 |
|---|---|---|
| iOS | `Info.plist`의 `UIAppFonts` | 폰트 파일 내부의 PostScript name |
| Android | `android/app/src/main/assets/fonts/` | 파일명 (확장자 제외) |

Android는 파일명으로 찾으니 `Fredoka_600SemiBold`가 맞다. 그러나 iOS는 파일명이 아닌 폰트 바이너리 안에 있는 PostScript 이름을 본다. 그리고 값은 Android와는 전혀 다른 이름인 `Fredoka-SemiBold`였다.

파일명과 PostScript 이름이 같은지 다른지는 폰트를 만든 사람 마음이라 규칙이 없다. 그래서 실제로 이 앱에 들어간 폰트도 OS에 따라 갈렸다.

| 파일 | Android가 찾는 이름 | iOS가 찾는 이름 |
|---|---|---|
| `Fredoka_600SemiBold.ttf` | `Fredoka_600SemiBold` | `Fredoka-SemiBold` |
| `Nunito_700Bold.ttf` | `Nunito_700Bold` | `Nunito-Bold` |
| `Nunito_800ExtraBold.ttf` | `Nunito_800ExtraBold` | `Nunito-ExtraBold` |
| `Nunito_900Black.ttf` | `Nunito_900Black` | `Nunito-Black` |
| `Pretendard-Bold.otf` | `Pretendard-Bold` | `Pretendard-Bold` |

`@expo-google-fonts/*` 패키지는 파일명에 언더스코어와 숫자 굵기를 쓴다(`Nunito_700Bold`). PostScript 이름은 하이픈 방식이다(`Nunito-Bold`).

그리고 한글 폰트로 쓴 Pretendard는 우연히 둘이 같았다. 그래서 본문 텍스트는 처음부터 멀쩡했고, 이 문제가 워드마크와 다른 버튼 라벨에서만 보였다. 그래서 아래와 같이 수정하였다.

```ts
const embeddedFont = (ios: string, android: string) =>
  Platform.select({ ios, default: android });

export const Fonts = {
  // Pretendard는 파일명과 PostScript 이름이 같아서 분기가 필요 없다
  body:             'Pretendard-Regular',
  bodyBold:         'Pretendard-Bold',
  bodyExtraBold:    'Pretendard-ExtraBold',
  bodyBlack:        'Pretendard-Black',

  rounded:          embeddedFont('Nunito-ExtraBold', 'Nunito_800ExtraBold'),
  display:          embeddedFont('Nunito-Black',     'Nunito_900Black'),
  displayBold:      embeddedFont('Nunito-Bold',      'Nunito_700Bold'),
  displayExtraBold: embeddedFont('Nunito-ExtraBold', 'Nunito_800ExtraBold'),
  splashWordmark:   embeddedFont('Fredoka-SemiBold', 'Fredoka_600SemiBold'),
} as const;
```

## PostScript 이름 확인하기

`fontconfig`에 딸려오는 `fc-scan`을 써서 폰트 이름을 먼저 확인했다.

```bash
brew install fontconfig

fc-scan --format "postscript=%{postscriptname}\nfamily=%{family}\nstyle=%{style}\n" \
  node_modules/@expo-google-fonts/fredoka/600SemiBold/Fredoka_600SemiBold.ttf
```

```
postscript=Fredoka-SemiBold
family=Fredoka,Fredoka SemiBold
style=SemiBold,Regular
```

`postscript` 값이 iOS에 쓸 이름이고, 파일명에서 확장자 뗀 게 Android에 쓸 이름이다.

여기서 `family`가 `Fredoka`와 `Fredoka SemiBold` 두 개로 나오는 것도 눈여겨보아야 한다. iOS에서는 family 이름으로도 폰트가 잡히긴 하는데, 이렇게 값이 모호하면 어느 쪽이 걸릴지 알 수 없다. 그래서 PostScript 이름을 쓰는 편이 안전하다.

만약 `fontconfig`를 안 쓰고 싶으면 fontTools로도 된다. name table의 nameID 6이 PostScript 이름이다.

```bash
pip install fonttools
python3 -c "from fontTools.ttLib import TTFont; \
  print([n.toUnicode() for n in TTFont('폰트.ttf')['name'].names if n.nameID==6][0])"
```

### 이 버그는 원래 없던 버그였다

처음부터 깨져 있었던 게 아니고 직전 작업에서 `useFonts`를 제거하면서 발생한 버그였다.

`useFonts`는 런타임에 폰트를 로드하면서 내가 지정한 JS 키를 양쪽 OS에 별칭으로 등록해준다. 그래서 이름을 하나만 써도 iOS와 Android 모두 같은 이름으로 폰트를 찾을 수 있었다.

그런데 작업하면서 폰트는 config plugin이 네이티브에 임베드하니까 런타임 로드는 중복이라고 판단해서 `useFonts`를 지웠다. 그리고 이로인해 폰트 이름 별칭이 사라졌고, 그때부터 폰트는 OS 네이티브 이름으로만 노출됐다. 결국, 이름이 우연히 같았던 Pretendard만 폰트가 깨지지 않아서 찾지 못한것이었다.

## Platform.select와 useFonts 중에 뭘 쓸까

|  | `Platform.select` | `useFonts` |
|---|---|---|
| 코드 | OS별 이름 2개를 관리 | JS 키 하나로 통일 |
| 첫 프레임 | 이미 로드돼 있어서 깜빡임 없음 | 로딩 완료까지 대기 필요 |
| Expo Go | 불가능 (네이티브 임베드가 필요) | 가능 |
| 실수 여지 | 이름이 틀리면 조용히 폴백 | 로드 전에 렌더되면 폴백 |

결국 우리 서비스에서는 `Platform.select`를 택했다. 폰트는 config plugin이 이미 네이티브에 임베드해서 첫 프레임부터 OS가 알고 있으니, `useFonts`를 되살리는 건 중복이라고 봤다. 대신 이름을 관리하는 부담이 생겼고, 위에서 말한 것처럼 틀렸을 때 찾기 어렵게 되기 때문에 향후 UI/UX 측면에서 변경이 발생한다면 `useFonts`를 되돌릴 선택지도 고려해보아야겠다.

## 폰트 고정에는 축이 하나 더 있다

패밀리를 고정해도 OS 글꼴 확대 설정은 별개로 남는다. 이건 앞의 버그를 잡기 전에 먼저 정리했던 부분이다.

처음엔 `fontFamily` 자체가 빠진 스타일이 열 군데 있었다. `fontWeight`만 지정하면 굵기는 맞지만 폰트는 Android에서 Roboto, iOS에서 SF로 그려진다. 

두 번째는 기기 글꼴 확대다. 상한을 안 걸면 iOS 접근성 최대 설정에서 3.56배까지 커진다. 이 앱은 카드와 버튼, 배지가 고정 높이라 그 정도로 커지면 글자가 잘린다.

`allowFontScaling={false}`로 아예 꺼버릴 수도 있었는데 그렇게는 안 했다. 글꼴 확대는 실제로 저시력 사용자가 쓰는 접근성 기능이고, 사용자가 키워놓은 글꼴을 이 앱만 무시하는 상황은 만들고 싶지 않았다. 그래서 배수 상한으로 절충해서 앱의 UI/UX를 해치지 않도록 했다.

```ts
export const MAX_FONT_SIZE_MULTIPLIER = 1.2;

export function Text({ maxFontSizeMultiplier = MAX_FONT_SIZE_MULTIPLIER, ...rest }: TextProps) {
  return <RNText maxFontSizeMultiplier={maxFontSizeMultiplier} {...rest} />;
}
```

1.2가 사용자들에게 적절한 값인지는 계속해서 확인을 해봐야하지만, 현재 UI/UX 상태에서 볼 수 있는 최적이라고 생각하였고 상수로 정리되어있기 때문에 추후 변경할수도 있다.

래퍼 컴포넌트를 만든 건 React 19 때문이다. 예전엔 `Text.defaultProps`에 한 줄 넣어서 전역으로 처리했는데, React 19에서 함수 컴포넌트의 `defaultProps`가 제거되면서 그 방법이 안 먹는다. 결국 `Text`와 `TextInput`을 감싼 래퍼를 만들고 38개 파일의 import를 옮겼다. JSX 본문은 안 건드려서 파일당 한 줄씩이었다.

같은 실수가 다시 나오는 걸 막으려고 lint 규칙도 걸었다.

```js
'no-restricted-imports': ['error', {
  paths: [{
    name: 'react-native',
    importNames: ['Text', 'TextInput'],
    message: "Text/TextInput 은 '@/components/ui/app-text' 에서 import 하세요.",
  }],
}],
```

## 확인은 눈으로 안 된다

글꼴 확대 상한은 텍스트 경계 상자를 측정해서 상한 있는 빌드와 없는 빌드를 비교했다.

| 조건 | 상한 적용 | 상한 없음 |
|---|---|---|
| iOS `accessibility-XXXL` | 1.20배 | 3.56배 |
| Android `font_scale 1.5` | 1.20배 | 1.53배 |

패밀리 고정은 Android 시스템 폰트를 Noto Serif로 바꾼 다음 스크린샷 픽셀을 비교했다.

| 영역 | 차이 픽셀 |
|---|---|
| 상태바 (시스템 UI) | 732 |
| 앱 본문 | 0 |

상태바가 732px 달라졌다는 건 시스템 폰트가 실제로 바뀌었다는 뜻이고, 앱 본문이 0이라는 건 그 변화가 앱에 안 새어 들어왔다는 뜻이다. 대조군이 있어야 이 숫자가 의미를 갖는다.

## 정리

새 폰트를 추가하는 절차는 폰트 파일을 `assets/fonts/`에 넣거나 `@expo-google-fonts/*`를 설치하고, `app.config.ts`의 `expo-font` plugin `fonts:` 배열에 경로를 추가하고, `fc-scan`으로 PostScript 이름을 확인하고, `constants/theme.ts`의 `Fonts`에 토큰을 추가한다. 이름이 다르면 `Platform.select`로 분기한다로 정리하였다.

마지막이 네이티브 리빌드다. `npx expo prebuild --clean` 후에 dev build를 다시 설치해야 한다. 그렇기 때문에 config plugin이 심는 건 네이티브 빌드 산물이라 JS 리로드로는 안 보이기 때문에 새 폰트가 안 나오면 코드보다 리빌드 여부를 먼저 확인하는 게 빠르다.

`fontWeight`는 아직 정리를 못 했다. `fontFamily`가 굵기별 파일을 직접 가리키고 있으면 `fontWeight`는 무시된다. 양쪽 플랫폼 스크린샷 픽셀 비교로 렌더 차이가 없는 건 확인했지만, 정석대로면 지우는 게 맞고 앞으로 고민해야할 사항 중 하나이다.
