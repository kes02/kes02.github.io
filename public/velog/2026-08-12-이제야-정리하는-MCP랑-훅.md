AI Agent가 당연시 되는 지금와서 이걸 정리하니 늦은감이 있지만, 나중에 까먹을 것 같아서 남겨둔다.

## MCP

MCP는 AI와 Tool(노션, 지라, 슬랙 등)과 같은 프로그램에 연결하기 위해 필요한 model context protocol이다. 그래서 MCP에는 클라이언트/서버가 또 나뉘어져 있다고 한다.

그래서 의문점은, 서버를 개발하면서 또 MCP를 위해 클라이언트/서버를 개발해야하는건가? 였다. 근데 이건 반만 맞았다. 내가 만들 건 MCP 서버 하나뿐이다. MCP 클라이언트는 Claude Code나 Cursor 같은 AI 앱(호스트) 안에 이미 들어있고, 내가 서버를 하나 붙이면 거기에 클라이언트가 하나씩 알아서 연결된다. 그러니까 이미 서버가 있으면 그걸 감싸는 얇은 MCP 서버 하나만 추가하면 되는 것.

비유를 하니까 이해가 쉬웠는데 AI가 먼저 서버한테 "너 뭐 할 수 있어?"를 물어보고 MCP 서버로부터 목록을 받아온다. 그리고 그걸 바탕으로 MCP에 연결된 툴이 요청한 대로 진행해주는 것이다.

- 나 = 식당에 메뉴판 보고 음식 주문하는 손님
- MCP 서버 = 메뉴판
- tool = 주방에서 실제로 음식을 만드는 것

즉, 여러 AI가 하나의 툴에서 뭘 제공하는지 정보를 받고, 그걸 Agent가 적재적소에 맞게 요청을 보내면 툴을 사용할 수 있는 것이다.

## 훅

이미 훅을 사용하고 있는데 훅이라는 것도 처음에 cronjob처럼 정해진 시점에 자동 실행되는 것을 의미하는 것일까? 라는 의문이 있었다. cronjob은 시간이 기준이고, 훅은 어떤 동작이 기준으로 완전히 다른 것이다.

여기서도 하나 틀리게 알고 있었다. 훅이 스킬을 실행시키는 게 아니었다. 훅은 정해진 이벤트에서 셸 명령을 하나 돌리고, 그 출력이 AI 컨텍스트에 끼어들어가는 구조다. i-have-adhd도 스킬이 아니라 SessionStart 훅으로 걸려있었고, 그래서 CLI를 새로 켤 때뿐 아니라 resume, clear, compact 할 때도 매번 뜬다.

내 settings.json을 열어보니 훅이 이렇게 걸려있었다.

- SessionStart: 세션이 시작될 때
- PostToolUse (Write, Edit): 파일을 쓰거나 고친 직후에 frontmatter 검사
- Stop: AI가 답을 끝냈을 때 work-log 기록

시점이 아니라 "무슨 일이 일어났을 때"로 걸려있는 게 확실히 보인다. 그리고 PreToolUse 훅은 AI가 도구를 쓰기 직전에 끼어들어서 그 실행을 아예 막을 수도 있다고 한다. 그러니 훅을 상황에 따라 적재적소에 뜨는 것도 좋은 방법인 것 같다.

## openclaw

맥북 한대가 집에 매번 있기 때문에 로컬 LLM을 돌리기에 좋다고 생각해서 찾다가, 예전에 팀원이 openclaw로 사용했던게 기억이 나서 이걸 사용하면 좋지 않을까 라고 생각했다. 이때는 이게 Agent라고 생각했다. 

근데 찾아보니 게이트웨이라고 한다. 한 마디로 ssh로 접속하지 않고도 슬랙이든, 텔레그램이든 이런 곳을 통해 "날씨 찾아봐줘" 이러면 openclaw에 연결된 Agent로 날씨를 찾아오는 것이었다. 그냥 채팅 하나로 AI한테 요청만 하면 MCP든, 훅이든 실행해서 가져오게끔 도와주는 툴이었다. 그래서 이걸 사용하려면 또 LLM API를 구매해야한대서 접었다...

근데 정리하면서 보니 내가 두 개를 섞어서 본 것 같다. 게이트웨이는 "어디서 말을 거느냐"를 담당하는 층이고, 어떤 모델을 쓰느냐는 그 뒤에 뭘 붙이냐의 문제라 원래 서로 별개이다. 애초에 openclaws를 사용할 수 있을까를 찾아보게 된 것은 로컬 LLM을 사용하고 싶어서였으니, API를 사야 한다고 접을 게 아니라 뒤에 로컬 모델을 붙일 수 있는지를 먼저 봤어야 했다.

현재는 ollma 모델을 로컬로 다운 받은 상태이고, openclaw에 붙여서 사용할지는 차차 고민해야할 것 같다. 현재 tailscae로 외부에서도 접속해서 사용할 수 있게 해둔 상태라 굳이 필요하지 않을 것 같기도 하다.
